# 技术规划

帮助技术负责人把业务问题和工程约束转成可讨论的投资选择与路线图。规划是判断顺序，不是固定模板：结论只到证据支持的范围，资源和不确定性要进入决策。

## 工作方式

1. **界定决定**：确认规划范围、时间跨度、读者和需要作出的决定。若信息不足但仍可推进，列待确认项和暂用假设；只有缺失信息会改变关键建议时才先提问。
2. **建立双引擎上下文**：业务分析说明服务对象、关键任务、阶段、瓶颈与变化；竞争分析检查用户替代方案、市场窗口、资金/盈利边界及技术/行业参照中哪些会改变目标水位或停止条件。用“约束—后果—证据”说明现状；只展开影响当前决定的维度。没有对标资料时标未知或待研究，不臆造竞品结论，也不为凑结构强行做全套对照。
3. **形成选项**：把业务/用户结果连接到能力缺口和工程动作；比较收益、投入、机会成本、依赖、失败影响和替代方案。ROI、容量或目标值缺数据时，给计算口径、假设和待补输入，不编数字。
4. **作出有边界的取舍**：说明做什么、暂缓/验证后再定/放弃什么，以及理由、责任人、决策权和重评或失效条件。按近期可承诺、中期可调整、远期看能力与信号表达路线图，不伪造远期确定性。
5. **定义验证**：列出结果指标、基线、目标、口径和窗口；尚无基线或目标时标为待确认，写出取得方式。补充依赖、验收、风险护栏和必要的回退路径。
6. **按用途输出**：采用用户需要的规划、摘要、表格或架构图格式。仅在用户要求或图能消除边界歧义时输出 Mermaid/PlantUML。
